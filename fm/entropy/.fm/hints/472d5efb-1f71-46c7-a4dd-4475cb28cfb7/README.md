# loss가 붕괴를 감지하지 못하는 근본적인 이유

> **한 줄 답.** 좋은 표현이 만족해야 할 조건은 둘(증강 불변 + 입력 정보 보존)인데, DINO loss는 그중 **불변성 하나만** 잰다. 상수 함수는 불변성을 *완벽하게* 만족하면서 정보를 전부 버린 해이므로, loss 눈에는 최고 점수로 보인다.

---

## 0. 먼저: "배치 축을 안 본다"는 논거와의 관계

형제 카드에서 다룬 구조적 논거 — `MiniDINOLoss.forward`의 모든 연산이 `dim=-1`(클래스 축)에서만 일어나고, 배치 축은 마지막 `.mean()`으로 평균낼 때만 등장한다 — 는 **증상의 위치**를 정확히 짚는다. "입력이 달라지면 출력도 달라지는가"는 본질적으로 배치 축을 가로지르는 질문이고, loss의 연산 그래프에는 그 질문을 던지는 자리가 아예 없다.

하지만 그건 *어디서* 정보가 새는지에 대한 답이지, *왜* 그런 손실을 쓰고도 DINO가 대체로 잘 되는지, 그리고 *왜 하필 손실이 거꾸로 된 신호를 주는지*에 대한 답은 아니다. 이 문서는 그 아래층 — **목적함수가 목적의 절반만 대리(proxy)한다**는 이야기 — 를 다룬다.

---

## 1. 불변성(invariance)과 정보량(informativeness)의 분리

self-supervised 표현 $f$ 가 쓸모 있으려면 두 조건이 **동시에** 필요하다.

| | 조건 | 형식화 | 상수 함수 $f \equiv c$ 는? |
|---|---|---|---|
| (i) | **불변성** — 같은 이미지의 다른 crop은 같은 출력 | $\mathbb{E}_x\,\mathbb{E}_{t_1,t_2}\big[d\big(f(t_1 x),\, f(t_2 x)\big)\big] \to 0$ | **완벽히 만족** ($d = 0$) |
| (ii) | **정보량** — 출력이 입력을 구별함 | $I\big(f(X);X\big) \to \max$ | **완전히 실패** ($I = 0$) |

DINO loss는 (i)만 직접 측정한다. 두 네트워크의 출력을 맞추는 것이 전부이기 때문이다. 그런데 (i)만 놓고 보면 상수 함수는 **전역 최적해**다 — 근사 최적이 아니라, 도달 가능한 최솟값을 정확히 달성하는 해다.

노트북 4절이 정확히 이걸 보여준다. `python3`로 재현하면:

```
one-hot collapse : loss = 0.0000     ← 모든 입력이 같은 차원 하나
healthy one-hot  : loss = 0.0000     ← 입력마다 다른 차원
uniform collapse : loss = 2.0794     ← log 8
```

붕괴한 모델과 건강한 모델의 loss가 **비트 단위로 같다**. loss는 두 상태를 구별할 언어를 갖고 있지 않다.

### 1-1. 왜 절반만 보이는지 — 정확한 분해

말로 하는 것보다 식이 훨씬 선명하다. teacher 출력 $q(x)$의 argmax를 그 입력의 **코드** $C$ 라 하고, 입력이 데이터셋에 균등 분포한다고 하자. 상호정보량의 정의에서

$$I(C;X) \;=\; H(C) - H(C\mid X) \;=\; \underbrace{h(\bar q)}_{h_{\text{mean}}} \;-\; \underbrace{\mathbb{E}_x\big[h(q(x))\big]}_{h_{\text{each}}}, \qquad \bar q = \mathbb{E}_x[q(x)]$$

한편 노트북 2절의 항등식 $H(q,p) = h(q) + D_{KL}(q\,\|\,p)$ 를 입력에 대해 평균내면

$$\boxed{\;\mathcal{L} \;=\; \mathbb{E}_x\big[H(q,p)\big] \;=\; \underbrace{h_{\text{mean}} - I(C;X)}_{=\;\mathbb{E}_x[h(q(x))]\;=\;h_{\text{each}}} \;+\; \mathbb{E}_x\big[D_{KL}(q\|p)\big]\;}$$

(단일 뷰 이상화에서 정확하고, 교차 뷰에서는 $D_{KL}$ 항이 뷰 간 불일치까지 흡수한다.)

**이 식이 카드의 답 전체다.** loss에 정보량 $I$ 는 등장하지만, 언제나 $h_{\text{mean}} - I$ 라는 **차이**의 형태로만 등장한다. 정보량을 늘리면 loss가 내려가지만, 코드를 덜 쓰는 것(=$h_{\text{mean}}$ 감소)으로도 똑같이 loss가 내려간다. 붕괴는 이 둘을 **동시에 0으로** 끌고 가면서 차이를 그대로 유지하는 경로다:

| | $h_{\text{mean}}$ | $I$ | $h_{\text{each}} = h_{\text{mean}} - I$ | $D_{KL}$ | $\mathcal{L}$ |
|---|---|---|---|---|---|
| 원-핫 붕괴 | $0$ | $0$ | $0$ | $0$ | **0** |
| 건강 (K개 코드 1:1) | $\log K$ | $\log K$ | $0$ | $0$ | **0** |

loss가 같은 이유가 "우연"이 아니라 **구조적 상쇄**임이 드러난다. 그리고 이 식은 노트북 5절이 왜 `h_each`와 `h_mean`을 **반드시 짝으로** 보라고 하는지도 설명한다 — 그 둘의 차이가 바로 loss가 못 보는 나머지 절반, $I(C;X)$ 이기 때문이다.

## 2. 그럼 왜 절반만 봐도 대개는 잘 되는가

목적함수가 (ii)를 안 보는데도 DINO가 ImageNet에서 잘 되는 이유는, **(ii)가 손실이 아닌 다른 곳에서 암묵적으로 강제되기 때문**이다.

| 암묵적 제약 | 어떻게 (ii)를 떠받치는가 | 깨지는 조건 |
|---|---|---|
| **centering** | 배치 평균 EMA를 로짓에서 뺀다 → 늘 큰 차원은 center도 커져 상쇄 → $h_{\text{mean}}$ 을 위로 민다 | `dist.all_reduce`가 도는 프로세스 그룹 미초기화, 아주 작은 배치, `center_momentum` 과대(논문 부록 D: $m=0.999$면 붕괴) |
| **sharpening** ($\tau_t = 0.04 < \tau_s = 0.1$) | teacher를 뾰족하게 → $h_{\text{each}}$ 를 아래로 민다 | $\tau_t > 0.06$이면 붕괴(논문 부록 D), warmup 없이 시작하면 반대쪽으로 과도 |
| **momentum teacher (EMA)** | teacher가 student보다 느리게 움직여 즉각적인 자기합의를 막는다 | $m$ 부적절, teacher를 student 복사본으로 대체(논문 Table 7 row 2: 수렴 실패) |
| **아키텍처 / 증강 강도** | 유한 용량 + 강한 증강이 자명해로 가는 경로를 험하게 만든다 | 증강 약화, head 용량 과잉 |

즉 정상 학습에서의 "loss ↓ ⇒ 표현 ↑"는 **목적함수가 보장하는 성질이 아니라, 위 장치들이 유지되는 동안에만 성립하는 우연한 상관**이다. 그리고 위험 구조가 여기 있다: 이 장치 중 하나가 흔들려도 **loss는 아무 경고를 내지 않는다.** 오히려 더 좋아 보이는 숫자를 낸다. 실전 함정 목록(노트북 6절)의 `all_reduce` 항목이 무서운 건 그래서다 — 단일 GPU 폴백에서 centering이 조용히 무력화되면, 대시보드의 loss 곡선은 평소보다 *더 예쁘게* 내려간다.

## 3. 최악의 부분 — loss는 무감각한 게 아니라 **역방향 신호**를 준다

"loss가 붕괴를 못 잡는다"는 표현은 사실 관대한 편이다. 노트북 5절을 그대로 실행하면(1500 step, 약 1~2분) 이렇게 나온다:

```
config                                  loss  h_each  h_mean   top_share  code_acc  n_codes
none        (center off, temp 0.1)      2.91    2.90    3.01        0.83      0.33        2
center only (center on,  temp 0.1)      3.37    3.36    3.46        0.33      0.83        6
sharp only  (center off, temp 0.04)     0.22    0.00    1.24        0.50      0.67        4
both = DINO (center on,  temp 0.04)     0.82    0.59    2.38        0.17      1.00        6

log K = log 32 = 3.47,  log 6 = 1.79,  1/6 = 0.17
```

**`sharp only`의 loss(0.22)가 건강한 `both = DINO`(0.82)의 4분의 1이다.** 그런데 표현 품질은 정반대다 — `both`는 6개 코드가 6개 클러스터에 1:1로 붙어 `code_acc = 1.00`, `sharp only`는 클러스터가 4개 코드로 뭉개져 한 코드가 데이터 절반을 먹고 `code_acc = 0.67`.

이건 늦게 벌어지는 일도 아니다. 궤적을 찍어 보면 **step 25**에서 이미 역전되어 끝까지 유지된다:

```
step     0  sharp= 1.929 acc=0.70 | both= 1.929 acc=0.73
step    25  sharp= 1.295 acc=0.67 | both= 1.622 acc=0.93   ← 여기서 이미 역전
step   250  sharp= 0.338 acc=0.67 | both= 0.878 acc=1.00
step  1499  sharp= 0.221 acc=0.67 | both= 0.816 acc=1.00
```

### 3-1. 그래서 무엇이 실제로 망가지는가

이건 "지표가 둔감하다"보다 훨씬 나쁜 상황이다. **loss를 기준으로 무언가를 고르는 절차는 전부 붕괴 쪽을 고른다.**

- **하이퍼파라미터 탐색**: 네 설정 중 loss 최저는 `sharp only`(0.22, `code_acc` 0.67). 자동 탐색이 loss를 목적으로 삼으면 붕괴 중인 설정을 우승자로 뽑는다.
- **early stopping / best-checkpoint**: "validation loss 최소 시점의 체크포인트"는 붕괴가 더 진행된 시점을 고르는 규칙이다.
- **모델 선택 상관관계**: 위 4개 설정에 대해 loss 순위와 `code_acc` 순위의 스피어만 상관은 **정확히 $\rho = 0.00$** 이다.

  | 설정 | loss 순위(낮은 순) | `code_acc` 순위(높은 순) |
  |---|---|---|
  | `sharp only` | 1 | 3 |
  | `both = DINO` | 2 | 1 |
  | `none` | 3 | 4 |
  | `center only` | 4 | 2 |

  $\rho = 1 - \dfrac{6\sum d_i^2}{n(n^2-1)} = 1 - \dfrac{6 \cdot 10}{4 \cdot 15} = 0$. 상관이 약한 게 아니라 **없다**.

### 3-2. loss 차이는 어디서 오는가 — 항별로 뜯어보면

같은 배치에서 $\mathcal{L} = h(q) + D_{KL}$ 로 쪼개 재보면 정체가 완전히 드러난다:

```
config        H(q,p)    h(q)      KL  |  h_each  h_mean   I = h_mean - h_each
none           2.917   2.908   0.009  |   2.901   3.008   0.106
center only    3.370   3.361   0.009  |   3.355   3.463   0.108
sharp only     0.290   0.051   0.239  |   0.003   1.242   1.240
both = DINO    0.954   0.645   0.309  |   0.587   2.376   1.789   ← = log 6 = 1.792
```

읽는 법:

1. **loss 순위는 $h(q)$ 순위와 거의 같다.** `sharp only`와 `both`의 loss 차이 0.66 중 0.59가 $h(q)$ 항이다. 즉 loss가 낮다는 건 대부분 "**teacher가 더 확신한다**"는 뜻일 뿐, "표현이 좋다"는 뜻이 아니다.
2. **$D_{KL}$ — 학습이 실제로 진전된 정도 — 은 건강한 쪽이 오히려 더 크다** (0.309 > 0.239). 논문 5.3절/Fig. 7이 "KL이 0으로 수렴하면 붕괴"라고 말하는 그대로다. 여기서 완전 붕괴한 두 설정의 KL은 0.009로, 정상 설정의 **1/30** 수준이다.
3. **$I(C;X)$ 는 표현 품질과 완벽히 같은 순서로 정렬된다** (1.79 > 1.24 > 0.11 ≈ 0.11). 그리고 `both`의 1.789는 $\log 6 = 1.792$ — 6개 클러스터를 정확히 6개 코드로 구별한다는 뜻이다. $\exp(I)$ 를 "**실효 코드 수**"로 읽으면 `both` 6.0개, `sharp only` 3.46개.

$I$ 는 loss 안에 있는 양이지만 언제나 $h_{\text{mean}} - I$ 로 묶여 나오므로 loss 값 하나에서는 복원할 수 없다. **따로 로깅해야만 보이는 절반이다.**

## 4. 일반화 — proxy objective의 함정

이 카드는 DINO에 관한 것이지만, 구조 자체는 SSL 전반에 공통이다.

$$\text{학습 손실} \;\;\xrightarrow{\;\text{대리}\;}\;\; \text{표현 품질} \;\;\xrightarrow{\;\text{대리}\;}\;\; \text{downstream 성능}$$

각 화살표는 "대체로 성립하는 상관"이지 항등식이 아니며, **상관이 깨지는 영역이 반드시 존재한다.**

| | 지도학습 | DINO 류 SSL |
|---|---|---|
| 손실의 target | 사람이 붙인 레이블 $y$ — **외부**에서 고정 | teacher 출력 $q$ — 모델이 **스스로** 만든 것 |
| target을 바꿔 손실을 낮출 수 있나 | **불가능** ($y$ 는 상수) | **가능** ($h(q)\!\downarrow$ 경로가 열려 있음, 노트북 2절 (b)) |
| loss ↔ 정확도 상관 | 강함 (같은 데이터 분포에선 거의 단조) | 영역에 따라 무너지고, 붕괴 근처에서는 **부호가 뒤집힘** |
| 자명해 | 없음 (상수 예측은 손실이 큼) | 있음 (상수 출력의 손실이 **최소**) |

핵심 차이는 **target이 최적화 변수에 종속되는가**다. 지도학습의 $y$ 는 상수라서 손실을 낮추는 유일한 길이 예측을 맞히는 것뿐이다. self-distillation에서는 teacher가 student의 EMA이므로 "**시험 문제를 스스로 쉽게 고쳐 쓰는**" 경로가 손실 안에 내장되어 있고, 붕괴는 그 경로의 종착점이다.

> **Goodhart's law**: "지표가 목표가 되는 순간, 그것은 좋은 지표이기를 그만둔다."
> DINO의 손실은 원래 좋은 지표였다 — 최적화 대상으로 삼기 전까지는. 붕괴는 최적화기가 "표현을 좋게 만들기"와 "지표를 좋게 만들기"가 갈라지는 지점을 찾아낸 결과다.

동류의 예: contrastive 손실의 negative가 부족할 때, BYOL에서 predictor를 빼면(논문 Table 14, rows 7–8), reconstruction 손실이 낮은데 표현은 저차원 텍스처만 담을 때, RL의 보상 해킹. 전부 같은 형태다 — **최적화 가능한 대리 목표는 정의역 어딘가에서 진짜 목표와 갈라진다.**

## 5. 그럼 무엇을 봐야 하나 — 손실 밖의 진단 신호

계산 비용 대비 조기 감지력 순으로 정렬했다. **위 세 개는 이미 loss 계산 중에 존재하는 값이라 비용이 사실상 0**이므로, 로깅하지 않을 이유가 없다.

| # | 신호 | 무엇을 잡는가 | 붕괴 시 값 | 비용 | 조기 감지력 |
|---|---|---|---|---|---|
| 1 | **$D_{KL}(q \Vert p)$** = `loss - h(q)` | **상수 출력**(완전 붕괴). 논문 Fig. 7의 주 지표 | $\to 0$ (측정: 0.009 vs 0.31) | **0** — 이미 계산된 두 항의 뺄셈 | 높음 |
| 2 | **`h_each`** = $\mathbb{E}_x h(q(x))$ | teacher의 **확신도**. 균등 붕괴 / 과확신 방향 | 균등→$\log K$, 원-핫→0 | **0** — teacher 출력에서 바로 | 높음 |
| 3 | **`h_mean`** = $h(\bar q)$ | **차원 사용률**. 원-핫 붕괴 | $\to 0$ | **0** — `q.mean(0)` 한 번 | 높음 |
| 4 | **$I = h_{\text{mean}} - h_{\text{each}}$**, $\exp(I)$ = 실효 코드 수 | **loss가 못 보는 나머지 절반 그 자체.** 부분 붕괴까지 | $\to 0$ (측정: 1.79 vs 1.24 vs 0.11) | **0** — 위 둘의 차 | **가장 높음** |
| 5 | **코드 사용 히스토그램** / `top_share` / 사용된 코드 수 | 어느 프로토타입이 죽었는지, 분포의 모양 | `top_share` $\to 1$ (측정: 0.17 vs 0.50 vs 0.83) | 낮음 — `argmax` + `bincount` | 높음, 시각적으로 즉시 |
| 6 | **feature effective rank** (특이값 엔트로피 $\exp(-\sum \tilde\sigma_i\log\tilde\sigma_i)$) | 차원 붕괴(dimensional collapse) — head 밖 표현까지 | 낮아짐 | 중간 — $B\times D$ SVD | 중간 |
| 7 | **k-NN 정확도** (`eval_knn.py`) | downstream 성능의 직접 대리. 학습 불필요 | 급락 | 높음 — train set 전체 임베딩 | 중간 (주기적으로만) |
| 8 | **linear probe** | 최종 판정 기준 | 급락 | 가장 높음 — 별도 학습 | 낮음 (사후) |

### 5-1. 실제로 어떻게 조합하나

- **매 step 로깅**: 1–4. 코드 세 줄이면 되고, 이 넷만으로 두 종류의 붕괴가 모두 구별된다.

  ```
                     h_each      h_mean       I
  원-핫 붕괴          → 0         → 0        → 0
  균등 붕괴          → log K      → log K     → 0
  건강              낮음         높음       → log(실효 클러스터 수)
  ```

  `h_each`/`h_mean` 을 **짝으로** 봐야 한다는 노트북 5절의 규칙은, 결국 "$I$ 를 보라"는 말이다.
- **에폭마다**: 5(히스토그램)와 6(rank). 코드 히스토그램은 붕괴가 *어떻게* 진행되는지 — 프로토타입이 하나씩 죽어 나가는 모습 — 를 보여주므로 디버깅에 특히 유용하다.
- **N 에폭마다**: 7. DINO 원본이 `eval_knn.py`를 따로 두는 이유가 이것이다.

### 5-2. 어디서 재느냐가 중요하다 (측정된 함정 둘)

- **effective rank는 재는 위치에 따라 부호가 뒤집힌다.** 위 4개 설정에서 teacher **로짓**의 effective rank는 `sharp only` 6.89 > `both` 4.75 로 **거꾸로** 나오지만, softmax 이후 **$q$** 에서 재면 `sharp only` 2.96 < `both` 5.07 로 올바르게 정렬된다. 손실이 실제로 소비하는 표현(또는 downstream이 쓸 표현)에서 재야 한다.
- **k-NN이 항상 통하는 건 아니다.** 이 토이에서는 입력이 2D이고 backbone이 2층이라 랜덤 초기화에서도 이웃 구조가 보존되어 k-NN이 늘 1.0이다(노트북 5절 주석). 실제 DINO에서 k-NN이 유효한 건 head의 붕괴가 12층 transformer 전체로 역전파되어 번지기 때문이다. **지표가 붕괴가 실제로 나타나는 층을 보고 있는지**를 항상 확인해야 한다.

$h(q)$/$D_{KL}$ 분해(3-2절)를 직접 보려면, 학습이 끝난 뒤 같은 배치에서:

```python
q    = F.softmax((teacher(v1) - center) / teacher_temp, -1)
logp = F.log_softmax(student(v2) / 0.1, -1)
H  = (-q * logp).sum(-1).mean()
hq = entropy(q).mean()
print(f"H={H:.3f}  h(q)={hq:.3f}  KL={H - hq:.3f}")   # both: 0.954 / 0.645 / 0.309
```

## 정리

1. loss는 **불변성**만 재고 **정보량**은 재지 않는다. 상수 함수는 불변성의 전역 최적해다.
2. 정확히 말하면, 정보량 $I$ 는 loss 안에 $h_{\text{mean}} - I$ 라는 **차이**로만 들어가서 붕괴 시 서로 상쇄된다. loss 값 하나로는 복원 불가능하다.
3. DINO가 대체로 잘 되는 건 centering·sharpening·momentum teacher가 정보량을 **암묵적으로** 떠받치기 때문이며, 그게 흔들리면 loss는 경고 없이 미끄러진다.
4. 최악은 무감각이 아니라 **역전**이다 — 붕괴 중인 설정의 loss가 건강한 설정보다 낮다(0.22 vs 0.82). loss 기준 모델 선택은 붕괴를 고른다. 측정된 순위 상관 $\rho = 0.00$.
5. 손실을 두 항으로 쪼개고($D_{KL}$), 엔트로피를 두 방향으로 재고(`h_each`/`h_mean`), 그 차이($I$)를 보라. 비용은 0이고, 이것이 loss가 못 보는 정확히 그 절반이다.

> 그래서 답은 이렇게도 쓸 수 있다: **loss는 "학생이 선생을 따라갔는가"만 묻고, "선생이 할 말이 있는가"는 묻지 않는다.** 아무 말도 안 하는 선생을 따라가기는 제일 쉽다.
