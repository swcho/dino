# `sharp only` — 붕괴가 "진행 중"인 상태를 알아보는 법

> **Q.** `sharp only` 설정의 결과 수치와 해석은?
> **A.** `h_each = 0`(모든 점이 확신에 찬 원-핫)인데 `h_mean ≈ 1.2`, `top_share = 0.5`다. 6개 클러스터가 ~4개 코드로 합쳐지고 한 코드가 데이터 절반을 먹는, 원-핫 붕괴의 초기 모습이다.

이 카드의 값어치는 숫자 세 개를 외우는 게 아니라 **"아직 완전히 무너지지 않았지만 무너지는 중"이라는 상태를 지표 조합으로 진단하는 법**에 있다.
아래 수치는 전부 `.fm/assets/dino_collapse_cross_entropy.py` 5절을 그대로 실행해 얻은 실측값이다(`torch 2.4.0`, CPU, seed 0, 1500 steps).

설정: `train(use_center=False, teacher_temp=0.04)` — centering 끔, teacher 온도 0.04(student 0.1보다 낮음 → sharpening만 켜짐).

## 1. 실측 표 — 네 설정 나란히

$K = 32$, $\log K = 3.4657$, 클러스터 6개($\log 6 = 1.7918$, $1/6 = 0.1667$).

| config | `loss` | `h_each` | `h_mean` | `top_share` | `code_acc` | 사용 코드 수 | `KL` |
|---|---|---|---|---|---|---|---|
| none (center off, temp 0.1) | 2.911 | 2.9012 | 3.008 | 0.833 | 0.333 | **2** | 0.0003 |
| center only (center on, temp 0.1) | 3.366 | 3.3551 | 3.463 | 0.333 | 0.833 | 6 | 0.0004 |
| **sharp only (center off, temp 0.04)** | **0.221** | **0.0028** | **1.242** | **0.500** | **0.667** | **4** | **0.047** |
| both = DINO (center on, temp 0.04) | 0.816 | 0.5870 | 2.376 | 0.167 | 1.000 | 6 | 0.065 |

`KL`은 노트북 `hist`에 없어서 따로 계산했다 — 클린 데이터 $X$에서 teacher 분포 $q$와 student 분포 $p = \mathrm{softmax}(f_s(X)/0.1)$ 사이의 $D_{KL}(q\|p)$ 평균이다.

파생 지표:

| config | $\exp(h_{\text{mean}})$ = 실효 코드 수 | 상호정보 $I = h_{\text{mean}} - h_{\text{each}}$ |
|---|---|---|
| none | 20.24 | 0.106 |
| center only | 31.92 | 0.108 |
| **sharp only** | **3.46** | **1.240** |
| both = DINO | 10.76 | 1.789 ← $\log 6 = 1.7918$에 거의 일치 |

카드 답의 세 수치(`h_each = 0`, `h_mean ≈ 1.2`, `top_share = 0.5`)는 그대로 재현된다. 다만 `h_each`는 **정확히 0이 아니라 0.0028**이다. teacher의 최대 확률을 찍어 보면 평균 0.999676, 최솟값 0.9836 — 실질적으로 원-핫이 맞다.

## 2. `h_each = 0`과 `h_mean ≈ 1.2`의 조합 읽기

이 둘은 **반드시 짝으로** 읽어야 한다.

- `h_each` = 점 하나하나의 분포 엔트로피 평균 → **"확신하는가"**. 0이면 모든 점이 완전한 원-핫.
- `h_mean` = 전체 점을 평균 낸 분포의 엔트로피 → **"차원을 골고루 쓰는가"**.

`h_each = 0` 하나만 보면 "완전 붕괴다"라고 착각하기 쉽지만, 원-핫 붕괴의 정의는 *모든 입력이 같은 차원으로 가는 것*이다. 그 상태라면 평균 분포도 원-핫이 되어 `h_mean`도 0이어야 한다. 그런데 여기선 1.242다 → **아직 모두 같은 코드로 간 게 아니다.**

$$\exp(h_{\text{mean}}) = \exp(1.2425) = 3.46$$

즉 실효적으로 3.5개 코드가 쓰이고 있다. 절반쯤 무너진 상태.

### 왜 `h_mean`이 정확히 1.2425인가

`h_each = 0`이면 각 점의 $q$가 완벽한 원-핫이므로, 평균 분포 $\bar q$는 **코드 사용 히스토그램 그 자체**가 된다. 실측한 $\bar q$의 상위 성분:

```
[0.50013, 0.16667, 0.16666, 0.16654, 1.0e-12, 9.3e-14]
```

정확히 $(1/2,\ 1/6,\ 1/6,\ 1/6)$이다. 손으로 계산하면

$$h_{\text{mean}} = -\left(\tfrac12\log\tfrac12 + 3\cdot\tfrac16\log\tfrac16\right) = 0.3466 + 0.8959 = 1.2425$$

실측 1.242와 소수 넷째 자리까지 일치한다. **`h_each = 0`일 때 `h_mean`은 코드 점유율 분포의 엔트로피와 정확히 같다** — 그래서 `h_mean` 한 숫자가 "몇 개 코드를 얼마나 균등하게 쓰는가"를 통째로 요약한다.

### 상호정보로 보는 "정보가 얼마나 남았는가"

$$I(\text{입력};\text{코드}) = h(\bar q) - \overline{h(q)} = h_{\text{mean}} - h_{\text{each}}$$

| 상태 | $I$ | 뜻 |
|---|---|---|
| both = DINO | **1.789** | $\log 6 = 1.7918$ — 6-way 클러스터 정보가 **전부** 남음 |
| **sharp only** | **1.240** | 정보가 **부분적으로** 남음 (완전 붕괴 0과 건강 1.79 사이) |
| 완전 원-핫 붕괴 | 0 | 출력이 입력에 대해 상수 |

$1.240 = \log 3.46$. 6-way 구분이 3.46-way로 줄었다는 정량 표현이다. `h_each`가 0으로 붙어버려 더 이상 정보를 못 담는 상태에서, 남은 정보량을 결정하는 건 오직 `h_mean` 하나다.

## 3. 클러스터 병합(merging) — confusion matrix로 확인

seed 0, 1500 steps. 행 = 원래 클러스터, 열 = 실제로 쓰인 코드 4개:

| cluster (원 위 각도) | c9 | c14 | c15 | c27 | 합 |
|---|---|---|---|---|---|
| 0 (0°) | 0 | 0 | **128** | 0 | 128 |
| 1 (60°) | **128** | 0 | 0 | 0 | 128 |
| 2 (120°) | 0 | 0 | **128** | 0 | 128 |
| 3 (180°) | 0 | **128** | 0 | 0 | 128 |
| 4 (240°) | 0 | 0 | 0 | **128** | 128 |
| 5 (300°) | 0 | 0 | **128** | 0 | 128 |
| **코드별 합** | 128 | 128 | **384** | 128 | 768 |

읽을 점:

1. **오염이 전혀 없다.** 각 클러스터의 128점이 통째로 한 코드로 간다. 클러스터 경계 자체는 완벽히 살아 있고, 다만 **세 클러스터가 한 코드를 공유**할 뿐이다. `code_acc = 0.667`은 정확히 $(128\times4)/768 = 4/6$ — 코드 c15에 묶인 세 클러스터 중 다수결로 하나만 맞고 둘은 틀린다.
2. `top_share = 0.5`는 $384/768$. **한 코드가 데이터 절반을 먹는다**는 게 이 숫자다.

대조군으로 `both = DINO`의 같은 표는 완벽한 대각선이다 — 6개 클러스터 ↔ 6개 코드(c17, c22, c24, c25, c27, c31) 1:1, 오염 0.

### 기하학적으로 인접한 것끼리 합쳐지는가? — **seed 0에서는 아니다**

노트북 서술은 "산점도에서 인접 클러스터들이 같은 색으로 묶인다"고 한다. 실측으로 검증하면:

- seed 0의 병합 그룹 = 클러스터 **{0, 2, 5}** = 각도 **{0°, 120°, 300°}**
- 쌍별 각도 차: 0–5는 60°(인접), 0–2는 120°, **2–5는 180°(정반대!)**

즉 **노트북이 실제로 그리는 seed 0 그림에서는 인접 병합이 아니다.** 원의 정반대 쪽 클러스터가 같은 코드를 쓴다.

seed를 바꿔 6번 돌려 보면 그림이 갈린다(3000 steps):

| seed | 코드 수 | `top_share` | `code_acc` | `h_mean` | 병합된 그룹 (각도) |
|---|---|---|---|---|---|
| 0 | 4 | 0.50 | 0.67 | 1.242 | {0°, 120°, 300°} ← **비인접** |
| 1 | 5 | 0.33 | 0.83 | 1.561 | {60°, 120°} 인접 |
| 2 | 4 | 0.33 | 0.67 | 1.330 | {0°,60°}, {120°,180°} 둘 다 인접 |
| 3 | 5 | 0.33 | 0.83 | 1.561 | {240°, 300°} 인접 |
| 4 | 3 | 0.33 | 0.50 | 1.099 | {0°,300°}, {60°,120°}, {180°,240°} 전부 인접 |
| 5 | 4 | 0.33 | 0.67 | 1.330 | {60°,120°}, {240°,300°} 둘 다 인접 |

**6개 중 5개 seed는 인접 병합이 맞다.** 노트북의 서술은 경향으로는 옳지만, 하필 노트북이 고정한 seed 0이 예외다. 그림에서 정반대 두 덩어리가 같은 색인 걸 보고 "버그인가?" 싶을 때의 답이 이것이다 — **어느 클러스터가 합쳐질지는 기하가 아니라 초기화 난수가 정한다.** 기하가 정하는 건 *몇 개까지 합쳐지는가*(다음 절)이지 *누가 합쳐지는가*가 아니다.

또 하나: `top_share = 0.5`는 seed 0의 특수 사정이다(3개가 한 코드로). 다른 seed는 2개씩 짝지어 0.33에서 멈춘다. **카드의 0.5는 "절반을 먹는다"는 정성적 메시지로 기억하되, seed 의존 수치임을 알아 둘 것.**

## 4. 왜 sharpening 단독은 병합으로 가는가

핵심 항등식으로 돌아간다:

$$H(q, p) = \underbrace{h(q)}_{\text{teacher 엔트로피}} + \underbrace{D_{KL}(q\|p)}_{\text{student가 teacher와 다른 정도}}$$

teacher 온도 0.04는 student 온도 0.1보다 훨씬 낮다. teacher 분포가 극단적으로 뾰족해지면 $h(q) \to 0$이 되어 **loss에서 $h(q)$ 항이 사라지고 $KL$만 남는다.** 실측 분해(증강된 view 기준, 20배치 평균):

| config | $H$ (= loss) | $h(q)$ | $D_{KL}$ | 확인: $h+KL$ |
|---|---|---|---|---|
| none | 2.9143 | 2.9063 | 0.0080 | 2.9143 |
| center only | 3.3688 | 3.3606 | 0.0082 | 3.3688 |
| **sharp only** | **0.2690** | **0.0478** | **0.2212** | 0.2690 |
| both | 0.9118 | 0.6320 | 0.2798 | 0.9118 |

`sharp only`에서 loss의 82%가 $KL$이다. **loss가 사실상 "teacher의 argmax를 맞혀라"는 하드 레이블 분류 문제로 바뀐 것이다.**

### 자기강화 승자독식(winner-take-all)

여기서부터가 병합의 메커니즘이다.

1. 초기 랜덤 상태에서 어떤 코드 $j$가 우연히 조금 더 많은 점의 argmax가 된다.
2. teacher가 뾰족하므로 그 점들의 타깃은 "코드 $j$"라는 하드 레이블이다. student는 코드 $j$의 로짓을 밀어 올리는 gradient를 **더 자주** 받는다.
3. 코드 $j$의 로짓이 전반적으로 올라가면, 경계선상에 있던(= 증강 노이즈로 crop이 겹치는) 옆 클러스터의 점들까지 argmax가 $j$로 넘어온다.
4. → 1로 돌아가 증폭. **양의 피드백 루프.**

centering이 있으면 3단계에서 제동이 걸린다. $\text{center} \leftarrow 0.9\,\text{center} + 0.1\,\overline{f_t(\text{batch})}$이므로 **늘 큰 차원은 center도 함께 커져서 $f_t - \text{center}$에서 상쇄된다.** 자주 뽑히는 코드일수록 페널티를 받는 음의 피드백이다. `sharp only`에는 이 제동이 아예 없다(`use_center=False` → `center = 0.0`).

궤적을 찍어 보면 이 루프가 **400스텝 안에** 끝난다:

| step | loss | `h_each` | `h_mean` | `top_share` | 코드 수 | KL |
|---|---|---|---|---|---|---|
| 0 | 1.929 | 1.1591 | 2.318 | 0.448 | 10 | 0.217 |
| 100 | 0.771 | 0.4279 | 1.592 | 0.500 | 5 | 0.051 |
| 200 | 0.444 | 0.1323 | 1.356 | 0.500 | 5 | 0.052 |
| 300 | 0.305 | 0.0578 | 1.296 | 0.500 | 4 | 0.044 |
| 400 | 0.287 | 0.0033 | **1.243** | 0.500 | **4** | 0.045 |
| 1499 | 0.221 | 0.0028 | 1.242 | 0.500 | 4 | 0.047 |

`h_each`(확신)와 코드 수(다양성)가 **동시에** 떨어진다. 10 → 5 → 4.

## 5. loss가 가장 낮다는 함정 ★

표를 다시 보라.

$$\text{loss}(\texttt{sharp only}) = 0.221 \quad<\quad \text{loss}(\texttt{both = DINO}) = 0.816$$

**loss만 보면 `sharp only`가 네 설정 중 압도적 1등이다.** 그런데 표현 품질은 정반대다 — `code_acc`가 0.667 대 1.000, 상호정보가 1.24 대 1.79.

이유는 분해식에서 바로 나온다. $H = h(q) + KL$인데 `sharp only`는 $h(q) \approx 0.05$로 첫 항이 거의 사라졌다. 남은 $KL = 0.22$는 "4지선다 하드 레이블"을 맞히는 비용이라 작다. 반면 `both`는 $h(q) = 0.63$을 **일부러 남겨 둔다** — teacher가 완전한 원-핫이 되지 않도록 centering이 붙잡고 있으니, 그 엔트로피가 loss에 그대로 더해진다.

> **loss를 낮추는 가장 쉬운 길은 teacher를 뾰족하게 만드는 것이고, 그건 붕괴로 가는 길이다.**

노트북 4절이 상수 출력으로 보여준 "loss는 붕괴를 못 잡는다"가 실제 학습 궤적에서 그대로 재현된 것이다. 4절에서는 원-핫 붕괴(loss 0.0000)와 건강한 원-핫(loss 0.0000)이 **같은** 값이었는데, 5절에서는 한 발 더 나가 **붕괴 쪽이 더 낮다.** 실전 함의는 명확하다 — loss 곡선이 예쁘게 떨어진다고 안심하면 안 되고, `h_each` / `h_mean` / `top_share`(또는 `eval_knn.py`)를 따로 로깅해야 한다.

| 3,000 | 0.299 | 0.0029 | 1.242 | 0.500 | 4 | 0.043 |

30,000스텝의 코드별 점유는 `{c15: 384, c9: 128, c14: 128, c27: 128}` — 1,500스텝과 완전히 동일. **진짜 고정점(fixed point)이다.** 400스텝에 도착해서 30,000스텝까지 미동도 없다.

sharpening을 더 세게 걸어도 소용없다(3000 steps):

| teacher temp | `h_each` | `h_mean` | `top_share` | 코드 수 |
|---|---|---|---|---|
| 0.04 | 0.0029 | 1.242 | 0.500 | 4 |
| 0.02 | 0.0000 | 1.242 | 0.500 | 4 |
| 0.01 | 0.0000 | 1.242 | 0.500 | 4 |
| 0.005 | 0.0000 | 1.242 | 0.500 | 4 |

`h_each`만 더 0에 붙을 뿐 코드 수는 그대로다. **온도는 "얼마나 확신하는가"만 정하고 "몇 개가 살아남는가"는 정하지 못한다.**

### 그러면 무엇이 4를 정하는가? — 증강 노이즈다 (단, 방향이 반대다)

σ를 쓸어 보면(3000 steps, seed 0):

| σ | `h_each` | `h_mean` | `top_share` | 코드 수 | `code_acc` |
|---|---|---|---|---|---|
| 0.0 (증강 없음) | 0.0006 | 1.488 | 0.487 | **8** | 0.678 |
| 0.2 | 0.0000 | 1.242 | 0.500 | 4 | 0.667 |
| 0.4 | 0.0000 | 1.242 | 0.500 | 4 | 0.667 |
| **0.7 (노트북 기본값)** | 0.0029 | **1.242** | **0.500** | **4** | 0.667 |
| 0.9 | 0.0379 | 1.237 | 0.500 | 4 | 0.667 |
| 1.0 | 0.0330 | 0.865 | 0.667 | 3 | 0.500 |
| 1.1 | 0.0085 | 0.011 | **1.000** | **1** | 0.167 |
| 1.2 | 0.0000 | **0.000** | **1.000** | **1** | 0.167 |
| 1.5 | 0.0000 | 0.000 | 1.000 | 1 | 0.167 |

**직관과 반대다. 증강 노이즈는 완전 붕괴를 *막는* 게 아니라 *일으킨다*.**

- σ = 0이면 두 crop이 완전히 같은 점이라 겹칠 일이 없다 → 코드가 8개나 살아남는다.
- σ가 커지면 다른 클러스터의 crop이 서로의 영역으로 넘어와 **"이 두 클러스터는 같은 것"이라는 잘못된 합의**를 강제한다. 승자독식 루프에 연료를 붓는 셈.
- σ ≥ 1.1에서 **완전한 원-핫 붕괴**에 도달한다: `top_share = 1.0`, `h_mean = 0`, `KL = 0.0000`, `code_acc = 0.167`(= chance $1/6$), 그리고 **loss = 0.000**.

즉 σ=0.7에서 4개에 멈추는 이유는 "노이즈가 붕괴를 막아서"가 아니라 **σ=0.7의 겹침이 딱 3개 클러스터를 묶을 만큼만 강해서**다. 노이즈가 클러스터 간격 대비 얼마나 큰지가 병합 규모를 정하고, 초기화 난수가 어느 클러스터가 묶일지를 정한다.

같은 σ=1.2에서 `both = DINO`를 돌리면 `code_acc = 1.00`, `h_mean = 3.451`, 코드 15개, `top_share = 0.17`이다. **centering만 켜면 완전 붕괴가 완전 해결로 뒤집힌다.** σ=1.2가 `sharp only`에게는 사형 선고이지만 `both`에게는 아무 일도 아니다.

## 7. 논문 Fig. 7과의 대응

논문(2104.14294v2) 5.3절 본문:

> A KL equal to zero indicates a constant output, and hence a collapse. […] If one operation is missing, the KL converges to zero, indicating a collapse. However, the entropy $h$ converges to different values: **0 with no centering** and $-\log(1/K)$ with no sharpening.

Fig. 7은 왼쪽에 teacher 타깃 엔트로피, 오른쪽에 teacher–student KL을 함께 그린다. 두 그림을 **같이** 봐야 하는 이유가 여기 있다:

- **엔트로피 곡선**은 어느 *종류*의 붕괴인지 알려준다. 0으로 가면 원-핫 붕괴(centering 없음), $\log K$로 가면 균등 붕괴(sharpening 없음).
- **KL 곡선**은 붕괴가 *일어났는지 여부*를 알려준다. KL = 0 ⟺ student가 teacher를 완벽히 복제 ⟺ 출력이 입력과 무관한 상수. 엔트로피 값 자체는 (예컨대 균등 붕괴의 $\log K$처럼) 건강한 값과 헷갈릴 수 있지만, KL = 0은 붕괴에만 나타난다.

토이에서의 대응:

| 논문 관찰 | 토이 실측 (σ=0.7, 노트북 기본) | 토이 실측 (σ=1.2) |
|---|---|---|
| sharpening only → $h \to 0$ | `h_each` 0.0028 ✔ **일치** | 0.0000 ✔ |
| sharpening only → KL → 0 | KL 0.047 (view 기준 0.221) ✘ **0이 아님** | **KL 0.0000** ✔ |
| centering only → $h \to \log K$ | `h_each` 3.3551 vs $\log 32 = 3.4657$ ✔ (97%) | — |
| centering only → KL → 0 | KL 0.0004 ✔ | — |

**차이의 해석**: 노트북 기본 설정(σ=0.7)의 `sharp only`는 논문이 말하는 *종점*이 아니라 **가는 도중**이다. 엔트로피는 이미 0에 닿았지만 KL이 0.047로 남아 있다 — student가 아직 4갈래를 구분하느라 할 일이 있다는 뜻이고, 그래서 상호정보도 1.24가 남아 있다. σ를 1.1 이상으로 올려 겹침을 키우면 KL도 0으로 떨어지며 논문 Fig. 7의 sharpening-only 곡선을 정확히 재현한다.

`none`과 `center only`가 KL ≈ 0.0003~0.0004로 이미 붕괴 판정인 것과 대비하면, **`sharp only`의 KL이 유일하게 0이 아니라는 사실 자체가 "아직 진행 중"의 정량적 증거**다.

# .fm/assets/dino_collapse_cross_entropy.py 정의를 로드한 뒤

for cl in range(6):
    print(cl, [(codes[y == cl] == c).sum().item() for c in sorted(codes.unique().tolist())])

## 한 줄 정리

`h_each = 0`은 **확신**의 증거, `h_mean = 1.24`는 **다양성이 절반 남았다**는 증거다. 둘의 차 $I = 1.24$(건강 1.79, 완전 붕괴 0)가 "붕괴 진행률"이고, `top_share = 0.5`는 승자독식이 이미 시작됐다는 신호다. 그런데 **loss는 0.221로 네 설정 중 가장 낮다** — 진단은 loss가 아니라 이 세 지표로 해야 한다.
