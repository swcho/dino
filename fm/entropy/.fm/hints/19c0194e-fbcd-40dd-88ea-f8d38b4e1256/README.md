# `q=one_hot, p=one_hot`일 때 loss = 0 — 그리고 그게 왜 재앙인가

> **Q.** `q=one_hot, p=one_hot`(둘 다 같은 원-핫)일 때 loss는 얼마이며 왜 문제인가?
> **A.** loss가 정확히 0인 완벽한 점수다. 입력이 무엇이든 이 한 쌍만 내면 되기 때문에 자명해(치트)가 되어 버린다.

---

## 1. 왜 정확히 0인가 — 분해의 두 항이 동시에 바닥을 친다

교차엔트로피의 항등식:

$$H(q, p) = \underbrace{h(q)}_{\text{target 분포의 엔트로피}} + \underbrace{D_{KL}(q \,\|\, p)}_{\text{student가 target과 다른 정도}}$$

두 항 모두 **음이 될 수 없다**($h(q) \ge 0$, $D_{KL} \ge 0$). 따라서 $H(q,p)$의 하한은 0이고, 그 하한에 도달하려면 **두 항이 동시에 0**이어야 한다.

| 항 | 0이 되는 조건 |
|---|---|
| $h(q) = 0$ | $q$가 원-핫 — 확률이 한 칸에 전부 몰려 있다 |
| $D_{KL}(q\|p) = 0$ | $p = q$ — student가 target을 완벽히 복사했다 |

`q=one_hot, p=one_hot`(같은 위치)은 이 두 조건을 **동시에** 만족하는 유일한 형태다. 그래서 $H(q,p) = 0 + 0 = 0$.

노트북 2절 표에서 실제로 확인되는 값 (자산 파일 `dino_collapse_cross_entropy.py`, $K=8$):

```
case                                    H(q,p)    h(q)      KL    h(q)+KL
q=peaked,  p=peaked  (완벽히 맞춤)        0.656   0.656   0.000     0.656
q=peaked,  p=uniform (student가 못함)     2.079   0.656   1.423     2.079
q=one_hot, p=peaked  (지도학습 상황)      4.148   0.000   4.148     4.148
q=uniform, p=uniform (둘 다 균등)         2.079   2.079   0.000     2.079
q=one_hot, p=one_hot (둘 다 같은 원-핫)   0.000   0.000   0.000     0.000  ← 유일한 0
```

바로 윗줄 `q=uniform, p=uniform`과 대비하면 요점이 선명하다. 거기서도 student는 target을 **완벽히** 따라갔다($KL=0$). 그런데 loss는 $\log 8 = 2.0794$다 — $h(q)$가 최대이기 때문이다. 즉 **$KL=0$만으로는 loss가 0이 되지 않는다.** $h(q)=0$까지 같이 눌러야 하고, 그러려면 target 분포가 뾰족해져야 한다.

DINO에서 target $q$는 레이블이 아니라 **teacher의 softmax 출력**이고, teacher는 student의 EMA다. 즉 $h(q)$를 낮추는 길이 최적화 입장에서 **열려 있다**. 이것이 붕괴의 통로다.

## 2. 자명해(trivial solution)의 정확한 의미

"자명해"는 "loss가 0이라서 나쁘다"가 아니다. 정확히는:

> **입력을 완전히 무시하는 상수 함수 $f(x) = c$ 가 loss의 전역 최소값을 달성한다.**

loss 함수 $H(q,p)$는 $f$가 상수인지 아닌지를 **전혀 벌하지 않는다**. loss의 정의에 입력 $x$가 들어가지 않기 때문이다 — 두 crop의 출력이 서로 일치하고 뾰족하기만 하면 만점이다.

노트북 4절이 이걸 실행으로 못 박는다. `MiniDINOLoss`(teacher_temp=0.04, student_temp=0.1, centering off)에 세 가지 상수/비상수 출력을 넣으면:

```python
B, out_dim = 16, 8

# (1) 원-핫 붕괴: 모든 샘플이 2번 차원에 큰 로짓 — 입력 무시
const = torch.zeros(B, out_dim); const[:, 2] = 50.0
# → loss = 0.0

# (2) 균등 붕괴: 모든 샘플이 전부 0 로짓
zeros = torch.zeros(2 * B, out_dim)
# → loss = 2.0794  (= log 8)

# (3) '건강한' 경우: 입력마다 다른 원-핫
healthy = F.one_hot(torch.arange(B) % out_dim, out_dim).float() * 50.0
# → loss = 0.0
```

**(1)과 (3)의 loss가 똑같이 `0.0`이다.** 이게 이 카드의 핵심이다.

- (1)은 16개 샘플이 전부 코드 2번을 가리킨다 — 출력에 입력 정보가 **0비트** 들어 있다.
- (3)은 16개 샘플이 8개 코드에 골고루 흩어진다 — 3비트가 살아 있다.
- loss는 둘을 **구분하지 못한다.**

표현 품질의 관점에서 (1)과 (3)은 정반대인데, 목적함수는 두 지점을 똑같이 "완벽"이라고 평가한다. 목적함수가 우리가 진짜 원하는 것(유용한 표현)을 **표현하지 못하고 있다**는 뜻이다.

참고로 `(2) 균등 붕괴`도 마찬가지로 상수 함수지만 loss가 $\log K$로 높다. 즉 균등 붕괴는 loss가 "안 좋다"고 말해 주기라도 하는데, **원-핫 붕괴는 loss가 만점을 준다.** 두 붕괴 중 원-핫 붕괴가 더 위험한 이유다.

## 3. 왜 최적화는 건강한 해가 아니라 붕괴 해로 끌리는가

두 해가 같은 loss 값 0을 준다면, 경사하강법은 **더 쉽게 도달할 수 있는 쪽**으로 간다. 그리고 상수 해가 압도적으로 쉽다.

**증강 노이즈가 난이도의 차이를 만든다.** DINO의 loss 항은 "같은 이미지의 서로 다른 crop 두 개가 같은 답을 내라"는 요구다.

- **건강한 해**를 만들려면: crop마다 픽셀이 흔들리는 입력에 대해, 이미지 정체성에는 반응하고 crop 노이즈에는 반응하지 않는 **진짜 불변(invariant) 표현**을 학습해야 한다. 게다가 서로 다른 이미지에는 **서로 다른** 답을 내야 한다. 이건 어렵고, 수많은 파라미터가 정확히 협응해야 한다.
- **상수 해**를 만들려면: 마지막 레이어의 **bias 하나만** 한 방향으로 키우고 weight를 0으로 죽이면 끝이다. 입력이 뭐든 같은 로짓이 나온다. 노트북 4절이 만든 `const[:, 2] = 50.0`이 정확히 그 상태다.

즉 loss landscape에서 붕괴 해의 **basin이 압도적으로 넓다**. 상수 출력에 가까운 파라미터 조합은 무한히 많고 아무 방향에서나 도달 가능하지만, 건강한 해는 좁은 계곡이다. 방지 장치 없이 SGD를 돌리면 거의 확실히 붕괴로 간다.

여기에 EMA teacher가 가속을 붙인다. student가 조금 뾰족해지면 teacher(= student의 EMA)도 뒤따라 뾰족해지고, 그러면 $h(q)$가 더 내려가면서 loss가 더 떨어진다 — **자기강화 루프**다. 브레이크가 필요한 이유이고, DINO의 답이 centering + sharpening이다.

## 4. 왜 실제 학습에서는 loss가 정확히 0이 되지 않는가

수학적으로 softmax는 **유한한 로짓으로 확률 1에 도달할 수 없다.** $K$차원에서 로짓 간극이 $g$일 때:

$$p_{\max} = \frac{1}{1 + (K-1)e^{-g}} < 1, \qquad -\log p_{\max} = \log\!\big(1 + (K-1)e^{-g}\big) > 0$$

즉 $g \to \infty$일 때만 loss가 0으로 **수렴**할 뿐, 어떤 유한한 $g$에서도 정확히 0은 아니다. 이론적으로 진짜 자명해는 **파라미터가 발산해야** 도달한다.

그럼 노트북은 왜 `0.0000`을 찍는가? **float32 유한 정밀도** 때문이다. 실제 계산($K=8$):

| 로짓 간극 $g$ | 수학적 $-\log p_{\max}$ | float32 $H(q,p)$ |
|---|---|---|
| 1 | $1.274$ | `1.274e+00` |
| 5 | $4.609\times10^{-2}$ | `4.609e-02` |
| 10 | $3.177\times10^{-4}$ | `3.177e-04` |
| 15 | $2.141\times10^{-6}$ | `2.146e-06` |
| **20** | $1.443\times10^{-8}$ | **`0.0`** ← 여기서 무너짐 |
| 50 | $1.350\times10^{-21}$ | `0.0` |

임계점의 근거: float32의 머신 엡실론은 $2^{-24}$이고, $1 - x$가 `1.0f`로 반올림되려면 $x < 2^{-25} \approx 2.98\times10^{-8}$이어야 한다. 따라서

$$(K-1)e^{-g} < 2^{-25} \iff g > \ln\!\frac{7}{2^{-25}} \approx 19.27$$

**로짓 간극이 약 19.3만 넘으면 float32 softmax는 실질적으로 완벽한 원-핫이 되고, $-\log 1.0 = 0$이 된다.**

노트북이 `50.0`을 고른 이유가 이것이다 — 임계점 19.3의 2.5배로, 여유 있게 넘긴다. 게다가 loss 안에서 로짓은 **온도로 나뉜다**:

- teacher: $50 / 0.04 = 1250$
- student: $50 / 0.1 = 500$

$e^{-500} \approx 7.1\times10^{-218}$은 float32의 최소 비정규수 $2^{-149} \approx 1.4\times10^{-45}$보다도 한참 아래라 **정확히 0으로 언더플로**한다. 그래서 softmax 결과가 비트 단위로 $(0,0,1,0,\dots)$이 되고, 실행 결과가 `0.0000`으로 나온다.

> 실제 DINO에서도 붕괴하면 loss가 0에 "아주 가깝게" 내려가지 정확히 0이 되지는 않는다. 하지만 로그에 찍히는 소수점 몇 자리 기준에서는 구분이 안 된다 — 그리고 그게 문제의 전부다.

## 5. 실전 함의 — 예쁜 loss 곡선은 학습 성공의 증거가 아니다

지도학습에서는 loss가 목표 그 자체다. loss가 내려가면 정확도가 올라간다.

**SSL에서 loss는 진짜 목표(유용한 표현)의 대리 지표(proxy)일 뿐이다.** 그리고 4절에서 봤듯 이 proxy는 붕괴 지점에서 **깨진다**. 붕괴한 모델의 loss는 건강한 모델과 같거나 **더 낮다**.

노트북 5절의 토이 학습 실험(2D 6클러스터, MLP student/teacher, 1500 step)이 이걸 실제 학습에서 재현한다. 직접 재실행한 최종 값:

| config | **loss** | `h_each` | `h_mean` | `top_share` | **`code_acc`** |
|---|---|---|---|---|---|
| none (center off, temp 0.1) | 2.91 | 2.90 | 3.01 | 0.83 | 0.33 |
| center only (center on, temp 0.1) | 3.37 | 3.36 | 3.46 | 0.33 | 0.83 |
| **sharp only** (center off, temp 0.04) | **0.22** | 0.00 | 1.24 | 0.50 | **0.67** |
| **both = DINO** (center on, temp 0.04) | **0.82** | 0.59 | 2.38 | 0.17 | **1.00** |

($\log 32 = 3.47$, $\log 6 = 1.79$, chance $= 1/6 \approx 0.17$)

**`sharp only`의 loss(0.22)가 `both = DINO`(0.82)보다 낮다. 그런데 표현 품질은 정반대다** — `code_acc`가 0.67 대 1.00이고, `sharp only`는 `h_each = 0.00`(모든 점이 확신에 찬 원-핫)에 `top_share = 0.50`(한 코드가 데이터 절반을 삼킴)으로 원-핫 붕괴가 진행 중이다. `both`는 6개 코드가 6개 클러스터에 1:1로 붙어 레이블 없이 클러스터링을 끝냈다.

loss만 보고 모델을 고르면 **더 나쁜 모델을 고른다.** 4절의 상수 출력 시연이 실제 학습에서 그대로 재현된 것이다.

### 그래서 무엇을 봐야 하는가

loss 대신(또는 loss와 함께) **출력 통계**와 **다운스트림 평가**를 봐야 한다:

| 지표 | 뜻 | 원-핫 붕괴 | 균등 붕괴 | 건강 |
|---|---|---|---|---|
| `loss` | 학습 손실 | $\downarrow 0$ | $\to \log K$ | 중간 |
| `h_each` | 점별 분포 엔트로피의 평균 — "확신하는가" | $\downarrow 0$ | $\uparrow \log K$ | 낮음 |
| `h_mean` | **평균 분포**의 엔트로피 — "차원을 골고루 쓰는가" | $\downarrow 0$ | $\uparrow \log K$ | 높음 |
| `top_share` | 가장 많이 쓰인 코드가 차지하는 비율 | $\uparrow 1.0$ | 노이즈 | $1/(\text{클러스터 수})$ |
| k-NN acc | `eval_knn.py` — 진짜 목표의 근사 | $\downarrow$ chance | $\downarrow$ | $\uparrow$ |

핵심은 **`h_each`와 `h_mean`을 짝으로** 보는 것이다. 자명해가 loss에는 안 보여도 이 짝에는 반드시 보인다:

- `h_each` **낮고** `h_mean` **높음** → "점마다 다른 차원을 확신 있게 고른다" = **건강**
- 둘 다 낮음 → "모두 같은 차원" = **원-핫 붕괴** (loss는 0에 가까움 — 여기가 함정)
- 둘 다 높음 → **균등 붕괴**

즉 loss가 못 보는 "입력이 출력을 바꾸는가"를 `h_mean`(배치 전체에 걸친 다양성)이 대신 본다.

> 실전 체크리스트: `eval_knn.py`를 주기적으로 돌리고, teacher 출력의 `h_each` / `h_mean` / `top_share`를 매 스텝 로깅한다. 실제 DINO는 $K = 65536$이라 $\log K = 11.09$가 균등 붕괴의 상한선이다.

## 6. 다른 SSL 방법은 자명해를 어떻게 막는가

모든 SSL 방법이 같은 문제를 안고 있다 — "두 view의 표현을 맞춰라"는 목적함수는 상수 함수로 만점을 받는다. 차이는 **상수 해에 어떻게 페널티를 주는가**다.

| 방법 | 상수 해를 벌하는 장치 |
|---|---|
| **Contrastive** (SimCLR, MoCo) | **negative pair.** 다른 이미지끼리는 표현이 **달라야** 한다는 항을 명시적으로 넣는다. 상수 출력이면 모든 negative의 유사도가 최대가 되어 loss가 폭발 — 자명해가 애초에 최소점이 아니게 된다. |
| **BYOL / SimSiam** | **predictor + stop-gradient.** negative 없이 online→target 비대칭 구조로 막는다. target 쪽 gradient를 끊어 "둘 다 같이 상수로 수렴하는" 지름길을 차단하고, predictor가 online을 target에 맞추게 해 붕괴 지점이 최적화 궤적의 불동점이 되지 않게 한다. |
| **Barlow Twins / VICReg** | **feature 차원 통계 제약.** 두 view 임베딩의 상관행렬을 항등행렬로 밀거나(중복 차원 제거), 배치 내 **분산이 일정 이상**이도록 강제한다(VICReg의 variance 항). 상수 출력은 분산이 0이라 이 항이 곧바로 폭발한다 — 상수 해를 **직접** 벌한다. |
| **DINO** | **centering + sharpening.** teacher 로짓에서 배치 평균의 EMA를 빼(centering) 한 차원 지배 = 원-핫 붕괴를 막고, teacher 온도($0.04$)를 student($0.1$)보다 낮춰(sharpening) 균등 붕괴를 막는다. 두 장치는 **서로 반대 방향으로 밀며**, 하나만 쓰면 반대편 붕괴로 간다 — 5절 표의 `center only`(균등 쪽, $h \to \log K$)와 `sharp only`(원-핫 쪽, $h_{\text{each}} = 0$)가 그 증거다. |

```python
teacher_out = F.softmax((teacher_output - self.center) / temp, dim=-1)
#                        └── centering ─────┘   └ sharpening
```

DINO의 특징은 negative pair도, predictor도, 명시적 분산 항도 없이 **이 한 줄의 두 연산만으로** 자명해를 회피한다는 점이다. 대신 그 대가로 두 하이퍼파라미터(`center_momentum`, `teacher_temp`)의 균형에 민감해진다 — `--teacher_temp`를 0.04에서 warmup으로 천천히 올리는 것도 초기에 sharpening이 너무 세면 원-핫 쪽으로 밀려 불안정해지기 때문이다.

## 한 줄 요약

$H(\text{one\_hot}, \text{same one\_hot}) = h(q) + KL = 0 + 0 = 0$ — 교차엔트로피의 **전역 최소값**이다. 문제는 이 최소값을 **입력을 무시하는 상수 함수도 똑같이 달성한다**는 것이고(노트북 4절: 붕괴 출력과 건강한 출력의 loss가 모두 `0.0`), 상수 해가 훨씬 쉽게 도달되므로 최적화가 그쪽으로 끌린다. 따라서 **SSL에서 loss가 0으로 떨어지는 것은 성공이 아니라 경보일 수 있다** — 출력 엔트로피 통계와 k-NN 평가로 따로 확인해야 한다.
